# Codex + Kimi Code 用量栏（本机版本）

基于 [Codex Usage Bar](https://github.com/yizhigou/codex-usage-bar) 的 MIT 许可代码，为这台 13 英寸 M1 MacBook Pro 添加了 Kimi Code 订阅额度。

## 显示内容

- 菜单栏：使用本机官方 Codex、Kimi Code 应用图标，显示两者 5 小时剩余额度、下一次额度重置时间和对应的小型工作状态灯。
- 展开菜单：各额度的进度与重置时间；Kimi 返回会员月总额度时也会列出。
- Touch Bar：每组两行显示 5 小时与周期余额、下一次额度重置时间，避免底部内容裁切；点击官方图标会启动或重新打开对应桌面应用、恢复最小化窗口并切到前台，不强制全屏。切换应用不再销毁重建 Touch Bar；登录、开盖和屏幕唤醒后仍自动恢复。常驻模式使用单独的系统模态会话，不再同时挂普通应用 Touch Bar；系统控制条入口会在重连、关闭模态或 ControlStrip 重启后自动重新注册。手动重新连接只重建一个新会话，不再杀掉 ControlStrip，避免“闪一下后丢失”的问题。
- Touch Bar 布局可在设置中选择“紧凑数字”或“双行余量条”。双行余量条按草图排列：官方 Logo、状态小灯、两条固定高度余量条，以及每行右侧的 `5h:百分比 时间`、`周/月:百分比 日期`。Codex 与 Kimi 共用同一套颜色规则：5h 余量为绿色、周期余量为柔白，低于 25% 变橙、低于 10% 变红，暂无数据使用灰色；颜色不按服务区分。
- Touch Bar 可选显示一枚 26 pt 的 IP 属地状态环：圆心使用 macOS 自带的 Apple Color Emoji 显示属地国旗，外环用蓝绿、黄、红、灰表示正常、验证失败、断网和未知。检测时高光沿环轻微旋转；轻点即时重新检测。具体公网 IP 不显示、不记录、不落盘，设置中可完全关闭该组件。
- 设置入口统一使用 SwiftUI 系统 Settings 场景，不再额外创建第二个同内容窗口，关闭按钮只需操作一次。
- “双行余量条”布局的余量条长度可在设置中调节为 60–110 pt，默认保持当前的 94 pt；设置使用无刻度连续滑块，Codex 与 Kimi 共用同一个长度值，拖动后即时更新，不重建 Touch Bar。常驻栏隐藏系统模态的左侧关闭按钮，避免误触退出。
- 状态小灯大小按布局分别可调：紧凑数字为 6–16.5 pt，双行余量条为 6–25 pt，默认 12 pt；两组服务共用尺寸，切换布局时会自动限制在对应范围内。
- 小灯固定在图标与额度之间：绿灯以 4.2 秒为一轮平滑呼吸（工作，吸气稍快、呼气更慢），黄灯以 5.8 秒为一轮慢速轻闪（等待批准或回答），暗白常亮（空闲）。完成时小灯内柔和彩虹流动并轻微明暗变化，约 3 秒后淡入暗白；失败时红灯轻亮两次后常亮；灰色空心表示未知。灯芯直径 5.5 pt，淡光晕从中心向外羽化，状态切换平滑交接；不移动、缩放或重绘额度。系统启用“减少动态效果”时改为静态显示；睡眠或关闭 Touch Bar 时停止动画。菜单中显示状态说明。
- 后台数据默认每 5 分钟同步；可在设置中调整为 1–60 分钟，也可手动同步。额度重置时会额外同步一次。后台同步时间与额度重置时间是两件不同的事；接口未提供重置时间时显示“未提供”。

Kimi Code 的新旧套餐可能返回不同的额度窗口。应用按服务实际返回的字段命名，不补造缺失的窗口。

## 登录与隐私

Codex 用量经本机 Codex `app-server` 的只读请求读取。Kimi Code 用量从官方 Kimi Code 额度端点读取，优先使用应用钥匙串中用户自行保存的 Kimi Code API Key；未配置时复用本机 Kimi Code 登录。登录过期时，会按 Kimi Code CLI 的续期协议更新同一份凭证，并使用 CLI 的文件锁，避免与 CLI 并发刷新。

API Key 保存在 macOS 钥匙串；凭证和额度不写入日志或上传到其他服务。此版本不使用 Moonshot 开放平台的按量计费余额。

工作状态在后台增量读取本机会话日志，只提取生命周期标记，不提取、保存或发送提示词。日志变动后约 0.2 秒合并更新，另有 5 秒兜底检查，与默认 5 分钟的额度同步互不影响。

Codex 使用当前应用启动后出现的任务开始、完成和中断记录；单次工具报错或可选异步提问不视为任务失败/等待。只有明确的运行时等待标记才能点亮黄灯，目前本机桌面日志未保证提供这些标记，不能可靠识别的情况不会伪造状态。10 分钟未变化的未结束记录转为未知，不误判空闲。

Kimi 使用 `event.session.work_changed` 的忙碌、待批准/回答与结束原因，兼顾后台任务；自动重试仍是工作状态，单个子任务结束不会清空会话的忙碌状态。应用/本机服务退出或重新启动后未收到新状态时为未知。多个本机会话按“等待 > 工作 > 最近结束状态”合并；云端、其他设备和不可访问的会话无法保证检测。

## 重新构建

本机命令行工具的 Swift Package Manager 与 SDK 版本暂不匹配；`build-local.sh` 使用已安装的 Swift 编译器和 macOS 15.5 SDK，生成 Apple Silicon 应用。

```sh
./build-local.sh
"dist/Codex Kimi Usage Bar.app/Contents/MacOS/CodexUsageBar" --self-test
```

应用构建为 ad-hoc 签名，不是 Apple 公证的发行版。Touch Bar 自动显示使用 AppKit 未公开接口，系统更新后可能失效；若失效，菜单栏仍可独立工作。

`screencapture -b` 只能验证软件生成的 Touch Bar 图像，不能证明实体屏幕发光。本机曾出现系统层 Touch Bar 黑屏；本应用可在登录或唤醒后重新建立自己的显示，但无法修复系统或硬件层面的黑屏。
macOS 会在长时间无输入时自动调暗 Touch Bar，本应用不强制阻止系统待机；轻触 Touch Bar 或键盘后应恢复显示。
